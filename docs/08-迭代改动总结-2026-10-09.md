## 二、本次（最后一段）的加固与验证

### 2.1 后端端口收口

发现 `ss -tlnp` 显示 Java 监听 `*:8080`（全网卡）。当时公网打不通，只是因为阿里云安全组拦着，  
而本机 `ufw` 处于 **inactive**、`iptables INPUT` 策略是 **ACCEPT** —— 等于整层防护押在一个随时可能被误改的云控制台开关上。

在 `portfolio.env` 追加 `SERVER_ADDRESS=127.0.0.1`（Spring Boot 自动绑定，无需改代码、无需重编译）。  
重启后监听变为 `[::ffff:127.0.0.1]:8080`，公网验证 HTTP 000，经 Nginx 的所有接口仍 200。

### 2.2 三项故障演练（都通过了）

| 演练            | 方法                            | 结果                                   |
| ------------- | ----------------------------- | ------------------------------------ |
| 进程崩溃自愈        | `kill -9` Java 主进程            | 10 秒后自动重建，PID 129898 → 130173，站点自动恢复 |
| Redis 单点故障    | `systemctl stop redis-server` | 站点首页/接口/登录全部 200（缓存层正确降级），恢复后正常      |
| 备份在 cron 下可执行 | `env -i` 精简环境跑备份脚本            | 10 秒完成，轮转到 2 份，退出码 0                 |

第二项很关键：**Redis 挂掉不会拖垮整站**，缓存失败会降级到直接查库。

### 2.3 自启状态

`portfolio` / `nginx` / `mysql` / `redis-server` 四者均为 `enabled`，`multi-user.target.wants` 软链齐全。  
`portfolio.service` 已声明 `After=network-online.target mysql.service redis-server.service`，  
`Restart=always` + `RestartSec=10`。**服务器重启后站点会自行恢复正常**，不需要人工介入。

## 四、⚠️ 只存在于服务器、不在 Git 里的东西

**这一节是本文存在的理由。** 仓库里没有下面这些，重建时必须手工补。

### 4.1 `/opt/portfolio/deploy/portfolio.env`

生产环境文件，含真实密码，**不入库**（已在 `.gitignore`）。本次追加了：

```
SERVER_ADDRESS=127.0.0.1
```

其余键（MySQL / Redis / JWT / 上传目录等）照 `deploy/env.production.example` 填。

### 4.2 crontab

```
root 身份下：
0 2 * * * /usr/bin/flock -n /var/run/pf-backup.lock bash /opt/portfolio/scripts/backup-ubuntu.sh >> /var/log/pf-backup.log 2>&1
```

每天 02:00 跑一次，产物在 `/var/backups/portfolio`，保留最近 2 份。  
**首次自动执行是部署后的第一个凌晨 2:00**，在此之前目录里只有手工跑出来的备份。  
次日用 `tail /var/log/pf-backup.log` 确认它真的跑过。

### 4.3 rclone

异地同步方案评估后决定**不采用**（站长明确否决），但 `apt-get install rclone` 已执行。  
无副作用，想清理可 `apt-get remove -y rclone`。备份脚本本身不含任何异地逻辑。

### 4.4 回滚能力

- 后端：退回到上一版只要把 `app.jar.bak-*` 复制回 `app.jar` 再 `systemctl restart portfolio`
- 前端：`web.bak-*` 是历史构建产物，同理
- 数据：`/var/backups/portfolio/db-*.sql.gz` + `scripts/restore-ubuntu.sh`

服务器上累积了 29 个 `*.bak-*` 占 384M（主要是 5 个 62M 的 jar）。  
磁盘还剩 29G，没有立刻清理的必要；要清时**务必保留最近的一份 jar 和一份 web**。

## 六、重建最短路径

```bash
1. 装 Nginx / MySQL 8 / Redis / JDK 17（MySQL、Redis 只监听 127.0.0.1）
2. git clone 仓库，按 deploy/env.production.example 填 portfolio.env
      ← 别忘了 SERVER_ADDRESS=127.0.0.1
3. mvn package 出 jar 放到 /opt/portfolio/app.jar
4. npm ci && npm run build，产物解到 /opt/portfolio/web
5. 拷 scripts/backup-ubuntu.sh 到 /opt/portfolio/scripts/，装第四节那份 crontab
6. 用 scripts/gen-theme-css.js 重新生成暗色样式（改过暗色 CSS 才需要）
7. systemctl enable --now portfolio nginx mysql redis-server
```

改过暗色样式后必须重跑第 6 步，否则手动切换主题时会漏掉新样式——这点已在 `MEMORY.md` 里记了。
