## 二、这个项目是什么

一个**个人影像作品集站点**（摄影 / 剪辑 / 直播搭建 / AI 视频制作），
核心价值不在于"能展示"，而在于**站长自己就能改内容，不用找开发、不用碰代码、不用重新部署**。

- 前台：单页站点，访客浏览作品、看视频、提交合作需求
- 后台：`/admin`，改文案、换素材、看访客数据、处理需求留言
- 数据：MySQL 存持久数据，Redis 做缓存（挂了自动降级到内存）

## 三、前台功能全览

路由只有三个：`/` 首页、`/login` 登录、`/admin` 后台。

首页由若干**内容模块**纵向拼接而成，模块可增删、排序、停用，全部在后台配置。

| 模块类型 | 作用 | 关键能力 |
|---|---|---|
| `hero` | 首屏主视觉 | 静音循环自动播放 Showreel；切后台暂停、回前台恢复 |
| `about` | 关于我 | 简介 + 关键事实（参数键值对） |
| `stack` | 作品画廊 | 卡牌横向叠加，点击展开播放；← → 切换 / Esc 收牌；果冻回弹动效；滚出视口自动收牌；**全局同时只允许一个视频在播** |
| `cases` | 案例展示 | 图文分栏 + 参数表 + 标签；多素材悬浮缩略轨 |
| `quote` | 金句通栏 | 大字引用，通栏玻璃卡片 |
| `contact` | 联系与工作对接 | 表单提交（姓名/联系方式/类型/预算/留言），滑动窗口限流 |
| `richtext` | 富文本 | 自由图文排版 |

### 3.1 案例模块的展示规则

这块改过两轮，规则是：

1. **画框跟随当前正在看的那条素材**的真实比例（不是锁死在第一条）
2. **完整显示不裁切**（`contain`）——摄影/剪辑素材的构图不能被替作者改
3. 切换素材时画框有 `aspect-ratio .4s` 平滑过渡，不跳版
4. 未点击时只显示封面：**手填封面 > 后端自动抽的视频首帧**
5. 鼠标移上去整块上浮 7px 并回弹（项目自带的 `--jelly` 曲线）
6. 视频**点一下才播**，播过之后控件保留
7. 尺寸元数据缺失时按方向猜比例（竖 9:16 / 方 1:1 / 横 16:9），不会先横后竖闪一下

### 3.2 昼夜主题

左下角常驻一个固定小窗（不随滚动移动），上方是实时时钟（年月日 + 时分秒，每秒刷新），
下方是"山 + 日月"的天色窗。

- 主题**自动跟随北京日出日落**，不用手动切
- 太阳白天沿山坡从左爬到右落下，夜里换成月亮走同一条弧线；位置由**真实时间插值**，不是循环假动画
- 天色随进程渐变：近地平线偏晨昏橙，中天是正午蓝，夜里深蓝带星
- 切主题瞬间全站颜色 1.2 秒渐变，不闪

算法在 `web/src/util/sun.ts`，用太阳赤纬驱动（与二十四节气同源），
坐标 39.9042N / 116.4074E。**上线前验证过**：夏至 04:47/19:47、冬至 07:33/16:53、
2026-10-09 06:19/17:46，与真实北京数据吻合。

### 3.3 素材保护

- 禁用右键菜单、拖拽另存、iOS 长按保存
- 播放器去掉下载按钮（`controlsList="nodownload"`）
- Nginx 层拦外站盗链：外站引用素材直接 403，本站正常访问不受影响

> **诚实说明**：浏览器能把视频播出来，就说明它已经拿到了完整数据。
> 上面这些挡得住顺手右键和长按，**挡不住会开 F12 的人**。
> 真要保版权靠的是画面水印 + 法律 + "只放低清预览"。

## 四、后台功能全览

入口 `/admin`，账号 `Cyan`。共六个板块：

### 4.1 模块
- 增删 / 排序 / 停用内容模块
- 中栏按模块类型**自动生成字段表单**（改类型就换一套字段，不用改代码）
- 保存后前台即时生效（会主动清 Redis 和本地缓存）

### 4.2 站点信息
- 站点标题、描述、链接等基础信息
- **历史快照**：每次保存留一份，自动保留最近 **10** 条并去重，
  内容没变化不重复存，可一键回滚

> ⚠️ 一个容易踩的机制：**快照存的是"保存前"的内容**。
> 所以想撤销刚才那次保存，要点列表里**最新**那条。方向别搞反。

### 4.3 素材库
- 上传 / 删除 / 分类 / 搜索
- 按"照片 / 视频"分开看
- **引用计数**：标出每条被引用几次；为 0 的是"孤儿素材"，可一键清理（二次确认）
- 视频自动生成首帧封面（见第六节问题 8）

### 4.4 监控
- 概览卡：今日访客、会话、播放数等
- 趋势图（近 7 / 14 / 30 天）、时段热力图
- 地域分布（省级）、设备分布、转化漏斗
- 只统计**匿名会话**：IP 只存哈希，不采集身份信息

### 4.5 工作对接
- 前台表单提交的合作需求都进这里
- 字段条理化、显示提交时间、标记状态、写内部备注
- 勾选后可**批量导出 CSV**（Excel / WPS 可直接打开）
- 勾选后可**批量删除**（两段式确认，见第六节问题 12）

### 4.6 账号
- 修改密码

## 五、状态显示标准（后台"显示什么"的依据）

后台首页的状态来自 `GET /api/admin/status`，字段与判定标准如下：

| 字段 | 含义 | 取值与判定标准 |
|---|---|---|
| `contentVersion` | 内容版本号 | 整数，每保存一次 +1 |
| `mediaCount` | 素材条数 | 素材库记录数 |
| `redis` | Redis 状态 | 见下方专表 |
| `uploadDir` | 素材存储目录 | 生产为 `/var/lib/portfolio/upload` |
| `maxUploadMB` | 上传大小上限（MB） | 当前 200 |
| `maxUploadText` | 上限的人类可读文本 | 当前 `200 MB` |

### 5.1 Redis 状态的三种显示

后端判定：
```java
String redis = props.isCacheEnabled()
    ? (cache.isRedisDown() ? "down" : "up")
    : "disabled";
```

前端映射（`AdminView.vue`）：

| 后端值 | 界面文字 | 实际含义 |
|---|---|---|
| `up` | **Redis 正常** | 缓存走 Redis，一切正常 |
| `down` | **Redis 已降级** | 最近一次 Redis 操作抛异常，暂时改用本机内存缓存 |
| `disabled` | **Redis 关闭** | `app.cache-enabled=false`，压根没启用 Redis |

### 5.2 看到"Redis 已降级"意味着什么

**站点不会挂。** Redis 里只放"丢了能重建"的数据（内容缓存、失败计数、token 黑名单），
真正的持久数据全在 MySQL。降级只是每次重新查库、略慢一点。

标志的复位规则（2026-10-09 修复后）：

- 任何一次 Redis 操作**抛异常** → 立即标记 `down`，并进入 **30 秒冷却期**
- 冷却期内不再尝试连 Redis（避免每请求疯狂重试）
- 冷却期过后，下一次操作**成功** → 自动复位为 `up`

所以：**Redis 恢复后，状态最多延迟 30 秒才会显示正常**。这是设计，不是故障。

> 排查顺序：先 `redis-cli -a <密码> ping`，返回 `PONG` 就说明 Redis 本身是好的，
> 那多半是标志还没过冷却期，等 30 秒再看。

### 6.1 本轮（2026-10-09）修复清单

| # | 问题 | 根因 | 解决办法 |
|---|---|---|---|
| 1 | 后端 8080 监听全网卡 | Spring Boot 默认绑 `0.0.0.0`；本机 ufw 是 inactive、iptables 全放行，防护全押在云厂商安全组上 | `portfolio.env` 加 `SERVER_ADDRESS=127.0.0.1`，重启即从进程层收口，**不用改代码重编译** |

| 4 | 案例画框四周露白边、四角冒白角 | 画框被第一条素材锁死 + `contain` 不裁切 → 横屏图塞进竖屏框上下留白，露出 `.ph` 占位底色 | 画框改为**跟随当前素材** + `aspect-ratio` 过渡；另加 `.ph.is-real.is-contain{background:transparent}` 兜底 |
| 5 | 金句通栏左上角有白色三角 | `.quote::before` 是一层锚在左上角的白色径向光斑，与玻璃卡片自带的镜面高光叠加，椭圆边界对不上圆角 | 整层移除（玻璃卡片自己的高光已足够，这层是重复装饰） |
| 6 | 素材可被随手下载 | 浏览器默认允许右键/拖拽/长按保存 | 禁右键+禁拖拽+禁 iOS 长按+`controlsList="nodownload"`+Nginx 防盗链（外站 403） |
| 7 | 服务器没有任何定时备份 | crontab 是空的 | 挂 `0 2 * * *` + `flock` 防重入，保留最近 2 份 |
| 8 | 启动日志刷"Using generated security password" | Boot 发现容器里没有 `UserDetailsService`，自己造了个内存账号 | 补一个"查任何用户都抛异常"的 bean，fail-closed 写法 |
| 9 | 工作对接只能导出，不能批量删除 | 功能缺失 | 新增"删除所选"，**两段式确认**（按钮变红"再点一次确认删除 N 条"，4 秒自动撤回） |
| 10 | 备份脚本报错 | 兜底库名写成 `Cyan`（生产是 `CyanWorks`）；mysqldump 缺 PROCESS 权限 | 修库名 + 加 `--no-tablespaces` |

| 12 | ffmpeg 抽帧失败 | 临时文件后缀不是图片格式，ffmpeg 猜不出封装格式 | 临时文件加 `.jpg` 后缀 |
| 13 | 手动切主题时系统暗色会盖回来 | 暗色 CSS 全在 `@media (prefers-color-scheme: dark)` 里，只有一套 | `scripts/gen-theme-css.js` 拆成"跟随系统"+"手动强制"两套 |
| 14 | 监控按年月日筛选 | 已实现后站长要求撤销 | 整体回滚（后端撤 `dailyAggregateBetween` 与 from/to，前端撤日期选择器） |

### 6.2 三个值得单独说的坑

#### ① 时区换算（问题 11）

```js
// 错
new Date(ms + (new Date(ms).getTimezoneOffset() + 480) * 60000)
// 对
new Date(ms + 480 * 60000)
```

`getUTC*` 读的是 UTC 墙钟，要让它等于北京墙钟只需加 8 小时。
叠加本地偏移在 UTC+8 机器上等于没加，显示成 UTC。
**这个错误是先写了测试脚本对答案才暴露的**——天文算法必须先验证再上线。

#### ② 暗色样式要拆两套（问题 13）

只加一个"强制暗色"覆盖是不够的：手动选白天时，系统暗色媒体查询仍会命中并把暗色盖回来，
白天根本切不动。必须拆成：

- `:root:not([data-theme="light"])` 跟随系统
- `:root[data-theme="dark"]` 手动强制

> **以后改暗色样式，必须重跑 `node scripts/gen-theme-css.js <css文件>`**，
> 否则新样式进不了"手动强制"那一套。

#### ③ 内容快照的方向（机制，不是 bug）

`ContentService.save()` 是**先把旧内容存为快照，再覆盖当前**。
所以快照存的是"保存前"的内容——想撤销刚才那次保存，要点列表里**最新**那条。
第一次做验收时按直觉选错了 id，白折腾一轮。

### 6.3 历史遗留的坑（以前踩过，记在这里防复发）

| 问题 | 根因 | 现状 |
|---|---|---|
| 后台改状态全部 405 | Nginx 方法白名单不含 `PATCH` | 已放行，三个配置文件都改了 |
| `/media/` 素材全 404 | **父目录**权限不足（不是路径不一致） | `chmod 755 /var/lib/portfolio` |
| Windows 打包上传后目录结构全丢 | `Compress-Archive` 写反斜杠路径 | 一律用 `tar.gz` |
| Git Bash 里 `tar` 报 `Cannot connect to C:` | 目标路径写成 `C:/...` | 必须写 `/c/...` |
| Ubuntu 服务名不对 | 是 `mysql.service` / `redis-server.service` | 不是 `mysqld` / `redis` |
| 文档说"保存后最多 5 分钟生效" | 过时 | 实测**即时生效**，save/rollback 都主动清了 Redis 和本地缓存 |

### 6.4 推送 GitHub 的两个障碍

1. **旧 token 失效** → 换 token。验证方式：`curl -H "Authorization: token <tok>" https://api.github.com/user`
   返回 200 才算有效。
2. **本机 `github.com` 直连超时**（`api.github.com` 却是通的）→ 让 git 显式走代理：
   ```bash
   git -c http.proxy=http://127.0.0.1:10677 -c https.proxy=http://127.0.0.1:10677 push origin main
   ```
   推完把 remote 改回不带凭证的 URL，别让明文 token 留在 `.git/config`。

## 八、故障演练结论（已验证）

这些是实测过的，不是推断：

| 场景 | 结果 |
|---|---|
| 后端进程崩溃（`kill -9`） | 10 秒后 systemd 自动重建，站点随之恢复 |
| Redis 挂掉 | 首页/接口/登录全部 200，缓存层正确降级 |
| 服务器重启 | 四个服务均 `enabled`，会自行恢复，无需人工介入 |
| 备份在 cron 环境下 | 10 秒跑完，正确轮转到 2 份 |

回滚方式：
- 后端退版 → 把 `app.jar.bak-*` 复制回 `app.jar` 再 `systemctl restart portfolio`
- 前端退版 → `web.bak-*` 同理
- 数据恢复 → `/var/backups/portfolio/db-*.sql.gz` + `scripts/restore-ubuntu.sh`
