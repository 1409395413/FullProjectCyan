> 面向"以后要自己维护、可能换服务器"的你。这一份回答三个问题：
> **这是个什么系统**、**它由哪些零件组成**、**零件之间怎么咬合**。

> 配套文档：`02-部署全流程SOP.md`（怎么装）、`03-运维与故障排查手册.md`（怎么养）、

## 一、一句话定位

一个**单页式个人影像作品集**（摄影 / 剪辑 / 直播搭建 / AI 视频），访客看前台、你进后台改内容。
核心设计一句话：

> **代码归代码，内容归内容。**
> 改文案、换图、加作品 = 后台点几下，**不用重新部署**；
> 改布局、加模块类型、改样式 = 改代码，**才需要重新打包上传**。

这条决定了整个架构：整站内容以 **一行 JSON** 存在数据库里，前端靠 schema 驱动渲染。

## 四、数据模型（10 张表）

`ddl-auto=update` 会自动对齐实体，但**生产以 `schema.sql` 为准**。

| 表 | 作用 | 关键点 |
|---|---|---|
| `site_content` | **整站内容，只有 1 行** | `payload` LONGTEXT 存 `{site, modules[]}`；`version` 自增 |
| `content_revision` | 每次保存的快照 | 改错了可回滚（`POST /api/admin/revisions/{id}/rollback`） |
| `admin_user` | 后台账号 | bcrypt 存密码；`role` owner/editor；`status` 1=启用 |
| `admin_session` | 会话表（预留） | 强下线靠 Redis 黑名单 |
| `media_asset` | 素材元数据 | **`path` 是相对路径**（`2026/10/uuid.mp4`），不暴露磁盘真实目录 |
| `inquiry` | 访客提交的工作对接 | name/contact/type/budget/message/status/note |
| `visit_session` | 匿名访问会话 | **只存 hash(IP+UA+日期)**，不采集身份信息 |
| `visit_event` | 曝光事件 | play / inquiry / contact_click |
| `audit_log` | 审计 | login / save_content / upload / delete_media … |
| （第 10 张） | 见 `schema.sql` | — |

> **设计亮点**：`site_content` 只存一行 JSON，所以**增删模块不用改表结构**，
> 前端渲染层按 `moduleSchema.ts` 自动排版。

## 六、内容模型（这是全项目最核心的设计）

整站内容就是一个 JSON：

```jsonc
{
  "site": { "brandName": "Cyan · Studio", "brandMark": "Cc",
            "footerNote": "...", "copyright": "...",
            "showBeian": true, "icpBeian": "", "policeBeian": "" },
  "modules": [
    { "id": "...", "type": "hero", "visible": true, "showNav": true,
      "navLabel": "首页", "size": "full", "fields": { ... } },
    ...
  ]
}
```

### 8 种模块类型

| type | 组件 | 用途 |
|---|---|---|
| `hero` | HeroModule | 首屏：眉标题 / 主标题 / 导语 / 标签 / 按钮组 / 数据条 |
| `about` | AboutModule | 关于我 |
| `stack` | StackModule | 能力栈 / 设备清单（列表） |
| `cases` | CasesModule | **作品区**，卡牌叠加画廊 |
| `quote` | QuoteModule | 引言 |
| `contact` | ContactModule | 联系方式 + 工作对接表单 |
| `text` | TextModule | 纯富文本 |
| `custom` | CustomModule | 自定义模块类型（后台可新建） |

### 字段是"schema 驱动"的

`web/src/moduleSchema.ts` 定义每种模块的字段（key / label / type / hint / options），
后台 `FieldsEditor.vue` 按 schema 自动生成表单，`ModuleSection.vue` 按 type 分发渲染组件。

**加一种新模块要动三处**：① `moduleSchema.ts` 加 schema ② `components/modules/` 加渲染组件
③ `ModuleSection.vue` 注册分发。后端**不用动**（payload 是 LONGTEXT，透传）。

字段类型：`text` / `richtext` / `switch` / `select` / `stringlist` / `list` / `group` / `media`。

## 七、素材存储机制（⚠️ 最容易踩坑的一环）

这是之前"换设备后素材全 404"的根因所在，务必理解：

```
浏览器上传
  → POST /api/media
  → StorageService.store()  落盘到  ${APP_UPLOAD_DIR}/yyyy/MM/uuid.ext
  → MediaAsset 表只存【相对路径】 "2026/10/uuid.mp4"
  → 前端拼成 /media/2026/10/uuid.mp4
  → Nginx location ^~ /media/  alias  ${APP_UPLOAD_DIR}/
     ★ Nginx 直出，不经过 Java
```

**三条铁律**：

1. `APP_UPLOAD_DIR` 必须是**绝对路径**（`./data/upload` 会相对 java 进程工作目录解析，
   换启动方式就写到别处去了）
2. 必须在**项目目录之外**（本机 `C:/Users/Administrator/portfolio-media`，
   服务器 `/var/lib/portfolio/upload`）——这样重新 clone / 重新部署不会误删素材
3. 后端 `WebConfig` 的 `/media/**` 映射 与 Nginx 的 `alias` **必须指向同一目录**，否则全站裂图

**当前值**：服务器 `/var/lib/portfolio/upload`，属主 portfolio。

## 八、安全机制清单

| 机制 | 实现 |
|---|---|
| 认证 | 自写 `JwtAuthenticationFilter`，从 `Authorization: Bearer` 或 Cookie 取 token |
| 密码 | BCrypt（cost 12），**永不明文落库** |
| 防账号枚举 | 用户名不存在时也跑一次等价 bcrypt，消除响应时间差 |
| 登录锁定 | 同 `用户名+IP` 失败 5 次锁 900 秒（Redis 计数） |
| 边缘限流 | Nginx `limit_req`：登录 12r/m burst 5；API 30r/s burst 40 |
| 应用限流 | `RateLimiter`（login 10 / api 120） |
| XSS | jsoup 白名单清洗（`HtmlSanitizer`），富文本只放行有限标签 |
| 响应头 | CSP / X-Frame-Options SAMEORIGIN / nosniff / Referrer-Policy / Permissions-Policy |
| 审计 | `audit_log` 记录 login / login_failed / save_content / upload / delete … |
| 隐私 | 访问统计只存 IP 哈希，不采集身份信息 |
| 上传 | MIME 嗅探（不是只看扩展名）、单文件上限 200 MB、nginx 侧 220 MB |

## 十、构建与打包

```powershell
# 本地 Windows（PowerShell）
.\pack-deploy.ps1          # → deploy.tar.gz（55.5 MB，23 条目）
```

内部 6 步：停后端 → 前端 `vue-tsc + vite build` → 后端 `mvn clean package` →
按白名单拷贝到 `_deploy_stage` → 脱敏 → `tar.exe -czf` 打包。

> ⚠️ 打包前**必须先停后端**：java 进程占用 `server/target/portfolio-server.jar`，
> Windows 删不掉被占用的文件，`mvn clean` 第一步就失败。

**打包格式必须是 tar.gz，不能是 zip**——原因见 `02-部署全流程SOP.md` 坑 #4。

## 十一、已知约束（别踩）

| 约束 | 值 | 后果 |
|---|---|---|
| 上传单文件 | 后端 200 MB / nginx 220 MB | 超过直接失败 |
| 内容缓存 | 300 秒 | 后台改完前台最多 5 分钟才更新 |
| 内存 | 2 GiB（swap 2 GiB 兜底） | JVM `-Xmx512m`，systemd `MemoryMax=1024M` |
| 并发 | MySQL `max_connections=60` | 别在这台机器上再跑别的服务 |
| 素材与数据库 | **必须同生共死** | 导了 SQL 不拷素材 = 前台裂图 |
