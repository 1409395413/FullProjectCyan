## 六、故障排查速查表

| 现象 | 最可能的原因 | 排查命令 |
|---|---|---|
| **502 Bad Gateway** | 后端没起来 | `journalctl -u portfolio -n 100`，多半是密码/端口写错 |
| 后端启动即连不上库 | `--apply-secrets` 没跑，或 `MYSQL_PORT` 写成 3307 | `grep MYSQL_PORT /opt/portfolio/deploy/portfolio.env` |
| **素材 404 / 前台裂图** | ① **父目录权限不足**（最常见，见下节）② `APP_UPLOAD_DIR` 与 nginx `/media/` alias 不一致 | `tail /var/log/nginx/error.log`，出现 `failed (13: Permission denied)` 就是 ① |
| Redis 起不来 | ① 用了 Docker 版 `redis.conf` ② `bind` 写了 `-::1` | `journalctl -u redis-server -n 50` |
| 后端无限重启 + YAML 报错 | `/opt/portfolio/config/application.yml` 被 Spring 加载了 | 该文件必须叫 `application.yml.example` |
| 内存吃满、进程被杀 | 没开 swap，OOM Killer 随机杀（常杀 MySQL） | `dmesg \| grep -i oom`；`swapon --show` |
| **后台改完前台没变** | Redis 缓存 TTL 300 秒 | 等 5 分钟，或立即清缓存（见下） |
| 登录提示"失败次数过多" | 同 用户名+IP 失败 5 次，锁 900 秒 | 等 15 分钟自动解锁 |
| 上传大文件失败 | 后端 200 MB / nginx 220 MB 上限 | 压缩后再传 |
| **竖屏视频被裁成横屏 / 视频位一片灰** | mp4 没做 faststart，浏览器要下完整个文件才有尺寸和首帧 | 见下节；上传时后端已自动处理 |
| 视频在手机上要等很久才开始播 | 同上，或文件本身太大 | 压到 5–8 MB；`-c copy -movflags +faststart` |
| **主页视频没有声音** | 浏览器禁止带声自动播放，不是故障 | 后台勾「允许播放声音」，前台出现喇叭按钮 |
| 域名打不开，返回 403 | **未备案**，阿里云拦截（`Non-compliance ICP Filing`） | 用 IP 访问；备案通过后自动解 |

### 素材 404：先怀疑父目录权限，别急着查路径

**nginx 的 `try_files $uri =404` 会把「权限不足」也吞成 404**，所以看到 404 时很容易
误判成"文件不存在 / 路径拼错"，白白查半天。先翻错误日志：

```bash
tail -20 /var/log/nginx/error.log
# 出现 stat() "/var/lib/portfolio/upload/..." failed (13: Permission denied) —— 就是权限问题
```

**根因**：`/var/lib/portfolio` 建目录时给的是 `750 portfolio:portfolio`。
nginx worker 以 `www-data` 运行，对该目录属于 others，`---` 表示连「进入（x）」都不行，
于是 `stat()` 直接 EACCES。`upload/` 下面的 755 / 644 再正确也没用——**父目录进不去**。

**修复**（两条都做，第二条是纵深防御，防止将来目录权限被改回去）：

```bash
chmod 755 /var/lib/portfolio          # 立即生效，reload 即可，不用重启 nginx
usermod -aG portfolio www-data        # 重启 nginx 后，即使目录回到 750 也仍能读
systemctl reload nginx
```

> 只需改 `/var/lib/portfolio` **这一层**。`upload/` 及 `yyyy/MM/` 是后端以 portfolio
> 用户建的，默认 755 / 644，本身没问题。

**验证**（三个都要看）：

```bash
curl -s -o /dev/null -w '%{http_code} %{content_type}\n' http://127.0.0.1/media/2026/10/xxx.jpg
curl -s -o /dev/null -w '%{http_code} %{content_type}\n' http://127.0.0.1/media/2026/10/xxx.mp4
# Range 请求必须返回 206，否则视频无法拖动进度条
curl -s -o /dev/null -w '%{http_code}\n' -H 'Range: bytes=0-1023' http://127.0.0.1/media/2026/10/xxx.mp4
```

### 视频：竖屏被裁成横屏、卡片显示灰块

**一个常被误判成"前端 bug"的问题，根因在文件本身。**

mp4 里有两个关键块：`moov`（索引：尺寸、时长、帧位置）和 `mdat`（真正的音视频数据）。
手机 / 相机 / 部分剪辑软件导出的文件是 `mdat` 在前、`moov` 在后：

```bash
# 看顶层 atom 顺序，moov 必须在 mdat 之前
python3 - <<'EOF'
import struct
f=open('/var/lib/portfolio/upload/2026/10/xxx.mp4','rb'); order=[]
while True:
    h=f.read(8)
    if len(h)<8: break
    s,t=struct.unpack('>I4s',h); order.append(t.decode('latin1'))
    s=struct.unpack('>Q',f.read(8))[0]-8 if s==1 else s-8
    f.seek(s,1) if s>0 else None
    if s<=0: break
print(' -> '.join(order[:6]))
EOF
# 输出 ftyp -> mdat -> moov 就是没做 faststart
```

这种文件浏览器必须**下载完整个文件**才有元数据。40MB 的视频在手机上基本等不到，于是：

- 尺寸探测不到 → 画框退回兜底的 `r-16-9` → 1080×1920 的竖屏被 `object-fit: cover` 裁成横屏
- 首帧渲染不出来 → `<video>` 一片空白 → 卡片是灰的，看不出传没传上

**修复**（纯重封装，不重编码，画质不变，秒级）：

```bash
ffmpeg -y -i in.mp4 -c copy -movflags +faststart out.mp4 && mv out.mp4 in.mp4
```

**后端已经自动做了**：`MediaService.faststartIfVideo()` 在每次上传视频后调用 ffmpeg，
并用 `ffprobe` 把宽高写进 `media_asset`。前提是服务器上装了 ffmpeg：

```bash
apt-get install -y ffmpeg     # Ubuntu；没装也不影响，代码会检测并跳过
```

> 前端另有双保险：`MediaItemEditor` 用 objectURL 读本地文件探测尺寸并抓封面帧
> （与文件多大、有没有 faststart 无关），视频会额外生成一张 poster 一起上传。

### 主页视频没声音：这是浏览器规则，不是 bug

所有现代浏览器都禁止**带声音的自动播放**——页面还没被用户交互过时，
带音轨的 `video.play()` 会被直接拒绝。所以首屏 Showreel 之类的自动播放视频，
**必须** `muted` 才能播起来，这不是配置错了。

项目里的做法（`MediaFrame.vue`）：

- 后台每个视频素材有一个 **「允许播放声音」** 开关（`MediaItem.sound`）
- 关（默认）：静音循环，不显示任何按钮
- 开：仍然**静音自动播放**（否则一开声就被浏览器掐掉），
  右上角多出一个喇叭按钮，访客点一下才真正出声——
  这一下点击正好满足浏览器要求的"用户手势"
- 非自动播放的视频（叠牌画廊点开、灯箱）本来就带 `controls`，
  声音由浏览器原生控件管理，不受这个开关影响

> 想改默认行为只能二选一：要么静音自动播放 + 访客点喇叭，
> 要么干脆不自动播放、放一个大播放按钮让用户点（点了就带声）。
> 没有"打开页面就自动出声"这条路。

## 八、换服务器迁移

**原则**：素材和数据库必须同生共死。

| 场景 | 做法 |
|---|---|
| **全新部署（推荐）** | 空素材目录 + `schema.sql` 建表 + 首次启动播种默认内容，后台重新上传素材。最干净 |
| **整机迁移** | 服务器上：`backup-ubuntu.sh` 出两个文件 → 传到新机器 → 按 `02-部署全流程SOP.md` 装完依赖 → `restore-ubuntu.sh` 恢复 |
| **本机 ↔ 服务器** | `toolchain/export-for-migration.ps1` / `import-for-migration.ps1`（Windows 侧） |

迁移后必查：`APP_UPLOAD_DIR` 指向新路径，且与 nginx `/media/` alias 一致。

## 九、改代码后的重新部署

1. 本地：`.\pack-deploy.ps1`（**先停本地后端**）
2. 上传新的 `deploy.tar.gz` 到 `/opt`
3. 服务器上：
```bash
systemctl stop portfolio
tar -xzf /opt/deploy.tar.gz -C /opt/portfolio     # 只覆盖 app.jar 和 web/
chown -R portfolio:portfolio /opt/portfolio
find /opt/portfolio -type f -exec chmod 644 {} +
chmod 600 /opt/portfolio/deploy/portfolio.env      # ★ 解压会重置权限，必须重设
systemctl start portfolio
```

> ⚠️ 重新解压后 `portfolio.env` 会被模板覆盖回默认值吗——**不会**（打包白名单不含 `.env`），
> 但权限会被重置，所以 `chmod 600` 这一步别漏。稳妥起见重新解压前先备份：
> `cp /opt/portfolio/deploy/portfolio.env /root/portfolio.env.bak`

> 只改**内容**（文案/图/作品）不需要这套流程，后台改完即可。
