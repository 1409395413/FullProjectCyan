## 三句话速览

1. **代码归代码，内容归内容** —— 改文案/换图/加作品走后台，不用重新部署；
   改布局/加模块类型/改样式才需要改代码重新打包。
2. **素材和数据库必须同生共死** —— 只导 SQL 不拷素材 = `media_asset` 有记录但磁盘没文件 = 前台全裂图。
3. **`APP_UPLOAD_DIR` 必须是绝对路径且在项目目录之外** —— 这是历史上唯一真出过故障的地方。

## 常用命令速查

```bash
# 服务状态（服务器上）
systemctl is-active portfolio nginx mysql redis-server
journalctl -u portfolio -f
curl -s http://127.0.0.1:8080/actuator/health

# 备份（服务器上）
bash /opt/portfolio/scripts/backup-ubuntu.sh /var/backups/portfolio

# 核对线上与仓库是否一致（本地执行，输出指纹表，对照 07 文档）
ssh -i Cyan.pem root@8.138.93.141 'bash -s' < scripts/verify-prod.sh

# 本地重新打包（Windows PowerShell，先停本地后端）
.\pack-deploy.ps1
```

完整版见 [03-运维与故障排查手册.md](./03-运维与故障排查手册.md)。

## ⚠️ 安全约定

- `.env`、`portfolio.env` 含数据库/Redis/JWT 密钥，**已被 `.gitignore` 排除，绝不进仓库**
- 打包产物（`deploy.tar.gz`、`portfolio-migration-*.tar.gz`）是构建输出，同样不进仓库
- 本文档中的密码一律写成占位符，真实凭据另行保管
- 服务器的 `/opt/portfolio/deploy/portfolio.env` 权限为 `600`，只有 root 可读
