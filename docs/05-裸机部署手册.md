# Cyan · Studio 裸机部署手册（Xshell + Xftp 传统方式）

> 适用：买云服务器 → Xshell 装依赖 → Xftp 传代码 → systemd 跑起来
> 系统：Ubuntu 22.04 / 24.04 LTS（推荐）

---

## 0. 先说结论

仓库里已经有一套**为裸机准备的自动化脚本**，核心就两条命令：

| 在哪执行 | 命令 | 作用 |
|---|---|---|
| 你的 Windows 本地 | `.\pack-deploy.ps1` | 编译前后端 → 只挑运行必需的文件 → 产出 `deploy.zip` |
| 服务器 | `sudo bash setup-ubuntu.sh --install-deps` | 装 JDK/MySQL/Redis/Nginx → 建用户目录 → 注册 systemd 与 nginx |

`pack-deploy.ps1` 打出来的 zip 内部结构（已和 nginx、systemd 的路径约定对齐）：

```
app.jar                          -> /opt/portfolio/app.jar
web/                             -> /opt/portfolio/web            (nginx root)
deploy/nginx.conf                -> /etc/nginx/conf.d/portfolio.conf
deploy/portfolio.service         -> /etc/systemd/system/portfolio.service
deploy/env.production.example    -> 复制成 portfolio.env 后填密码
deploy/redis.conf                -> Redis 配置（裸机要改，见第 5 步）
db/schema.sql                    -> 建表脚本
DEPLOY.md                        -> 自动生成的详细文档
setup-ubuntu.sh                  -> 服务器初始化脚本
```

**本地构建环境已确认齐全**：JDK 17.0.20.1、Maven 3.9.11、Node 22.22.2、npm 10.9.7 —— 可以直接打包，不用额外装东西。

## 1. 买服务器和域名

**服务器选型**

| 项目 | 建议 |
|---|---|
| 配置 | 2 核 2G 是最低可用，**2 核 4G 更舒服**（MySQL 8 空跑就要 400~500MB） |
| 系统 | Ubuntu 22.04 LTS |
| 厂商 | 阿里云 / 腾讯云 / 华为云 |
| 带宽 | 3~5 Mbps 起步（图片站别选 1M） |
| 安全组 | 放行 **22 / 80 / 443**，其余一律不放（尤其 3306、6379、8080 绝不能对公网开） |

**域名**：在哪买都行，买完加一条 A 记录指向服务器公网 IP。

> ⚠️ **国内服务器必须备案**，否则 80/443 会被拦，网站打不开。备案通常要 10~20 天，建议买完服务器就先提交。不想备案就用中国香港或海外节点，但访问速度会慢一些。

## 2. Xshell 连接服务器

新建会话 → 主机填公网 IP → 端口 22 → 用 root 或 sudo 用户登录。

连上后先做两件事：

```bash
sudo apt update && sudo apt upgrade -y
sudo ufw allow 22/tcp && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp && sudo ufw enable
```

## 3. 本地打包（Windows PowerShell）

```powershell
cd C:\Users\Administrator\WorkBuddy\2026-10-08-10-28-14\FullProjectCyan
.\pack-deploy.ps1
```

脚本会自动：检测技术栈 → 编译前端（`npm run build`）→ 编译后端（`mvn clean package`）→ 白名单收集 → **扫描并脱敏敏感配置** → 生成 `deploy.zip`。

产物在项目根目录：`deploy.zip`（约几十 MB，不含 `node_modules` 和 `.git`）。

常用参数：
- `-SkipFrontend` / `-SkipBackend`：跳过某一侧构建，复用上次的产物
- `-KeepStage`：保留 `_deploy_stage` 暂存目录，方便排查

> 打包前确认 `web/dist` 和 `server/target/*.jar` 是新的，别把旧产物传上去。

---

## 4. Xftp 上传并解压

用 Xftp 连同一台服务器，把 `deploy.zip` 拖到 `/opt/portfolio/`（目录不存在就先建）。

然后在 Xshell 里：

```bash
sudo mkdir -p /opt/portfolio
cd /opt/portfolio
sudo unzip -o deploy.zip
sudo chmod +x setup-ubuntu.sh
sudo bash setup-ubuntu.sh --install-deps
```

`--install-deps` 会装：`openjdk-17-jre-headless`、`mysql-server`、`redis-server`、`nginx`，并创建 `portfolio` 系统用户、建好 `/var/lib/portfolio/upload` 与 `/var/log/portfolio`、注册 systemd 和 nginx 配置。

> 脚本默认**不启动**后端，因为密码还没填 —— 这是对的，按下面几步来。

---

## 5. 配置 MySQL 和 Redis

### 5.1 建库建用户

```bash
sudo mysql -uroot
```

```sql
CREATE DATABASE IF NOT EXISTS Cyan
  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;

CREATE USER IF NOT EXISTS 'Cyan'@'127.0.0.1'
  IDENTIFIED BY '换成强密码-至少16位';

GRANT ALL PRIVILEGES ON CyanWorks.* TO 'Cyan'@'127.0.0.1';
FLUSH PRIVILEGES;
EXIT;
```

导入建表脚本（可选，但推荐）：

```bash
sudo mysql -uroot Cyan < /opt/portfolio/db/schema.sql
```

> 即使不导也没关系 —— `JPA_DDL=update` 会在首次启动时自动建表并对齐实体。
> 生产跑稳之后建议把 `JPA_DDL` 改成 `validate`，防止误改表结构。

### 5.2 Redis 密码：已脚本化，不用手改配置

> 这一步已由项目修复好。**不要手改 `/etc/redis/redis.conf`**，也不要用 `deploy/redis.conf`（那是 Docker 版，`dir /data` 在裸机上不存在，且故意不写 `requirepass`）。

仓库新增了裸机专用的 `deploy/redis-ubuntu.conf`，`pack-deploy.ps1` 会打进包。填完 `.env` 后执行：

```bash
sudo bash /opt/portfolio/setup-ubuntu.sh --apply-secrets
```

它会自动：备份原配置 → 用裸机版覆盖 → 把 `__REDIS_PASSWORD__` 替换成 `.env` 里的真实密码 → 校正 `MYSQL_PORT=3306` → 重启 Redis 并验证 `PONG`。**可重复执行**，改密码后重跑即可。

手工验证：

```bash
redis-cli -a '你的密码' ping      # 返回 PONG 即成功
systemctl status redis-server
```

## 6. 填写环境变量

```bash
cd /opt/portfolio/deploy
sudo cp env.production.example portfolio.env
sudo chmod 600 portfolio.env
sudo vim portfolio.env
```

必须改的几项：

```ini
MYSQL_PORT=3306                        # 后端默认已是 3306，显式声明双保险
MYSQL_PASSWORD=刚才建用户的密码
REDIS_PASSWORD=刚才设的 Redis 密码
JWT_SECRET=用 openssl rand -hex 48 生成
ADMIN_PASSWORD=后台管理员初始密码
APP_CORS_ORIGINS=https://你的域名
APP_UPLOAD_DIR=/var/lib/portfolio/upload
```

生成 JWT 密钥：

```bash
openssl rand -hex 48
```

**systemd 的 EnvironmentFile 格式很严格**，写错就启不来：
- 一行一个 `KEY=VALUE`，**不要写 `export`**
- 值**不要用引号**包裹
- 值里别出现空格、`$`、反引号

## 7. 应用密钥并启动

填完 `.env` 后，先让脚本把 Redis 密码注入到位：

```bash
sudo bash /opt/portfolio/setup-ubuntu.sh --apply-secrets
```

看到 `Redis 已就绪（密码校验通过）` 再启动后端：

```bash
sudo systemctl daemon-reload
sudo systemctl start portfolio
sudo systemctl enable portfolio      # 开机自启

# 看日志（Ctrl+C 退出）
sudo journalctl -u portfolio -f
```

验证：

```bash
curl http://127.0.0.1:8080/actuator/health     # 应返回 {"status":"UP"}
sudo nginx -t && sudo systemctl reload nginx
```

然后浏览器访问服务器公网 IP，能看到站点就说明通了。

常用运维命令：

```bash
sudo systemctl status portfolio
sudo systemctl restart portfolio
sudo tail -f /var/log/portfolio/app.log
```

## 8. 配置 HTTPS

先把 nginx 配置里的域名改掉（`server_name` 默认是 `_`，certbot 认不出来）：

```bash
sudo vim /etc/nginx/conf.d/portfolio.conf
# server_name _;  ->  server_name 你的域名 www.你的域名;
sudo nginx -t && sudo systemctl reload nginx
```

签发证书：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名 -d www.你的域名
```

certbot 会自动改 nginx 配置并配好自动续期。验证续期：

```bash
sudo certbot renew --dry-run
```

**手工部署 HTTPS**（不用 certbot --nginx 时）：把 `deploy/nginx-ubuntu-tls.conf` 复制成 `/etc/nginx/conf.d/portfolio.conf`，替换域名占位符：

```bash
sudo cp /opt/portfolio/deploy/nginx-ubuntu-tls.conf /etc/nginx/conf.d/portfolio.conf
sudo sed -i "s|__DOMAIN__|example.com|g; s|__WWW_DOMAIN__|www.example.com|g" \
     /etc/nginx/conf.d/portfolio.conf
sudo nginx -t && sudo systemctl reload nginx
```

> 这个裸机版模板已修好 Docker 版的三个问题：上游指向 `127.0.0.1:8080`（不是 8081）、静态资源走 `root` 直出（不再 proxy_pass）、补回了 `/media/` alias 与限流。
> 仓库里另一个 `deploy/nginx-tls.conf.example` 仍是 Docker 版，裸机**不要用**。

## 9. 以后怎么更新

```powershell
# 本地
git pull
.\pack-deploy.ps1
```

Xftp 上传新的 `deploy.zip` 到 `/opt/portfolio`，然后：

```bash
cd /opt/portfolio
sudo unzip -o deploy.zip
sudo systemctl restart portfolio      # 后端换了才需要
```

前端是纯静态文件，覆盖 `web/` 即刻生效，**不用重启 nginx**。

## 11. 换服务器 / 换设备迁移（保证素材不丢）

> **如果是全新部署、不迁素材**：跳过本节。
> `setup-ubuntu.sh --install-deps` 会建好空的 `/var/lib/portfolio/upload`，
> 数据库按第 5 步用 `schema.sql` 建表即可，首次启动会自动播种默认内容和管理员。
> 已核实 `default-content.json` **不含任何 `/media/` 引用**，所以全新安装不会出现裂图，
> 直接在后台重新上传素材就行。
>
> ⚠️ **唯一要避免的组合**：导了 `cyan.sql` 但不拷 `media/`。
> 那样 `media_asset` 表里有记录、磁盘上却没文件，前台会一片裂图/空视频。
> 要么素材和数据一起迁，要么都不迁（全新安装），别各迁一半。

### 核心原则：素材目录必须在项目目录之外，且 `APP_UPLOAD_DIR` 写绝对路径

数据库里存的只是**相对路径**（如 `2026/10/78f077e4a4584939.mp4`），后端拿它拼上 `APP_UPLOAD_DIR` 去找真实文件。

一旦 `APP_UPLOAD_DIR` 写成相对路径（例如 `./data/upload`），它相对的是**进程启动时的工作目录**——
换个目录 clone 项目、重新打包部署、systemd 的工作目录不一样，拼出来的路径就变了，
结果就是「后台明明传成功了，前台 `/media/**` 全部 404」。**这是本次故障的根因。**

| 环境 | 推荐的素材目录 |
|---|---|
| Windows 本机 | `C:\Users\<你>\portfolio-media` |
| Linux 服务器 | `/var/lib/portfolio/upload`（安装脚本已自动创建，属主 portfolio） |

Nginx 的 `/media/` alias 必须指向同一个目录，否则一样 404。

### 旧机器：导出

```powershell
powershell -ExecutionPolicy Bypass -File .\toolchain\export-for-migration.ps1
```

产出仓库根目录下的 `portfolio-migration-<日期>.tar.gz`，内含：

- `media/` —— 全部素材，**保持 `2026/10/xxx.mp4` 相对结构**（和库里存的一致，这是能直接复原的关键）
- `cyan.sql` —— 全库 dump（含 `site_content` / `media_asset` / `admin_user`）

### 新机器：恢复

Windows 本机（一条命令，会自动建库、导入、并校验素材数 vs `media_asset` 行数）：

```powershell
powershell -ExecutionPolicy Bypass -File .\toolchain\import-for-migration.ps1
```

Linux 服务器：

```bash
tar -xzf portfolio-migration-*.tar.gz -C /tmp
mkdir -p /var/lib/portfolio/upload
cp -r /tmp/media/. /var/lib/portfolio/upload/
chown -R portfolio:portfolio /var/lib/portfolio/upload

mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS Cyan DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql -uroot -p CyanWorks < /tmp/cyan.sql

systemctl restart portfolio
```

### 恢复后自检

```bash
# 素材能取到（200，不是 404）
curl -I https://你的域名/media/2026/10/78f077e4a4584939.mp4

# 后端自己认为的素材目录 + 素材数量
curl -u 登录态 https://你的域名/api/admin/status
# 重点看 uploadDir 是不是你期望的绝对路径、mediaCount 是否等于实际文件数
```

## 附：踩坑速查

> 下面前两项已在本轮修复：MySQL 默认端口改成了 3306、新增了裸机专用 Redis 与 HTTPS 配置。
> 保留在表里是因为如果你拉的是修复前的旧包，仍会遇到。

| 现象 | 原因 |
|---|---|
| 后端连不上 MySQL | 用了旧版本 jar，其 `application.yml` 默认兜底 3307；现在默认是 3306，且 `--apply-secrets` 会校正 |
| Redis 起不来 / 数据不落盘 / 无密码 | 用了 `deploy/redis.conf`，`dir /data` 是 Docker 路径且不写 `requirepass`；改用 `redis-ubuntu.conf` + `--apply-secrets` |
| systemd 启动报环境变量错误 | `portfolio.env` 里写了 `export` 或给值加了引号 |
| `/media/` 图片全部 404 | `APP_UPLOAD_DIR` 用了相对路径（换目录启动即失效），或和 nginx 的 alias 不一致；详见第 11 节 |
| 网站打不开 | 国内服务器未备案，或安全组没放行 80/443 |
| 后台传视频失败 | nginx 的 `client_max_body_size` 太小（HTTPS 模板里是 220m） |
